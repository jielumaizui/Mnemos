## 六、审计结论

**链路13 测试验证层当前结论：状态隔离闭环；模块语义覆盖继续由 function matrix/分层测试演进。**

- ✅ runner：quick/integration/system/heavy/full 共用 hermetic 环境所有权；CI 三平台不含 shell 专属 sandbox 命令
- ✅ diagnostics/full-score：显式环境 hash、正式状态 diff、repo diff 和每 gate 日志
- ✅ 默认安全：零 API 凭据、只读诊断、唯一写探针、非空输出根拒绝复用
- ✅ 当前分母：Quick 5776 + 15 subtests、System 6；Integration 279、Heavy 18 为最近完整层证据
- ⚠️ 正式 runtime producer/consumer 账本中的业务待消费回执属于运行态真值，不通过清账、扩预算或测试 shim 处理

**下一步建议：**

1. 修改测试/门禁入口时运行 `python3 scripts/audit_gate_hermeticity.py --suite diagnostics --strict --json --output-dir <empty-temp-dir>`。
2. 外部模型测试显式注入 provider/client；只有发布 full-score `--real-api` 使用真实凭据。
3. 覆盖缺口、死代码和运行态账本问题继续按各自 function/resilience contract 处理，不混入 hermetic 边界放宽。

### 7.5 关键发现

1. **Kimi `data_dir` 逻辑**：当 `KIMI_HOME` 的 `sessions` 子目录不存在时，会回退到 `KIMI_HOME` 父目录；但测试显示，若 `~/.kimi/sessions` 真实存在，标准路径会优先于 env 父目录返回。
2. **Claude `claude_data_dir` 配置项**：当前 `core.config.Config.claude_data_dir` 仅检查固定文件系统路径，未读取配置文件中的 `claude_data_dir` 字段；`claude_source.py` 的相关分支实际不可通过配置触发。
3. **Codex UUID session_id 提取**：`re.search(r"([a-f0-9-]{36})", jsonl_file.name)` 在 `rollout-<uuid>.jsonl` 文件名中可能匹配到前导 `-`，导致 session_id 以 `-` 开头；测试已按实际行为断言包含 UUID 即可。
4. **Kimi 用户未知块 loss**：`_pair_messages_to_turns` 在每次处理 `role == user` 后都会重置 `completeness_loss`，因此用户消息中的未知 content 块虽被记录到 `raw_event_refs`，但不会进入 `loss_reasons`。
